Viva & Technical Documentation

College project architecture, algorithms, and DSA reasoning

1. Why No Graphs / Adjacency Lists?

In university computer science syllabi up to Trees, students have not yet covered Graph theory, BFS, DFS, or Adjacency Matrices. This project strictly fulfills the requirements using Classes, Objects, and ArrayLists. Friendships are simply mutual entries in each User object's ArrayList<String> friends list.

2. Algorithm Explanations for Viva Questions

  • Mutual Friends Logic: Takes two users, gets their respective friend lists, and performs a for loop nested comparison. If friend1.equalsIgnoreCase(friend2), it's added to the common list. Time Complexity: O(F1 × F2).
  • Friend Suggestions Logic: Loops through each direct friend F of user U, then loops through each friend FoF of F. If FoF != U and !U.isFriend(FoF), it is added to the suggestion list with a mutual friend counter.
  • Preventing Duplicates: Linear search loop across ArrayList<User> before insertion.
  • Network Statistics: Single-pass loop calculating sum of friend counts. Total friendships = totalDegrees / 2 because every friendship is mutual.

3. Technology Architecture

• Backend: Pure Java (JDK built-in com.sun.net.httpserver.HttpServer). Zero heavy external dependencies (no Spring Boot, no Maven/Gradle required to run).
• Frontend: Modern responsive HTML5, CSS3, and JavaScript with interactive HTML5 Canvas visualization.
